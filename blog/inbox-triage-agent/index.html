A shared inbox isn't one problem, it's four

A shared business inbox isn't a queue of similar messages. Most of what lands in one sorts cleanly into four kinds of thing, and each one wants something different from whoever opens it:

  • A new enquiry, which needs a fast, specific reply or it goes to whichever competitor answers first.
  • A complaint, which needs a person, not a template, and needs to be seen quickly regardless of how it's worded.
  • A supplier or admin message, which usually needs filing or a short routine reply, not real attention.
  • Noise: newsletters, receipts, out-of-office replies, the stuff that has to be opened to confirm it's nothing.

The problem is that all four arrive looking the same in a list view, so triage becomes reading every subject line and the first sentence of every message to figure out which bucket it's in, before you've even started answering anything. That sorting pass is pure overhead. It doesn't move any single task forward, it just decides what order to do things in, and it has to happen before the real work starts.

Two hours a day of that, which is a realistic number for a small team sharing one inbox, is $1,540 a month at $35 an hour. None of that time goes to actually answering a customer. It goes to figuring out which messages are customers.

What the Inbox Triage Agent on the catalog page does is exactly that sorting pass: read the inbox, decide which of the four buckets each message belongs to, draft the routine replies in the admin and noise buckets, and leave the enquiry and complaint buckets for a person with the context already pulled together. It doesn't decide what to tell an angry customer. It makes sure the angry customer's message is the first thing a person sees instead of the fortieth thing they read trying to find it.
